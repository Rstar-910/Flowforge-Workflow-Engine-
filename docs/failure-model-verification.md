# Verifying the failure model against the code

`docs/failure-model.md` claims a behaviour for each failure scenario and names a test.
This document records, for each claim:

1. **How the failure is induced**, and whether it is *real* (an actual process, signal or
   network event) or *simulated* (database state set directly).
2. **Evidence that the failure actually happened**, so a test can't pass vacuously.
3. **Where the outcome is checked.** The rule throughout is that outcomes are asserted
   by querying PostgreSQL rows. Logs are used only as evidence that a failure was
   exercised, never as the outcome.
4. **Which mutation proves the test bites.** The protection is removed from the source
   and the test must fail. See [mutation-results.md](mutation-results.md), regenerated by
   `uv run python scripts/mutation_check.py`.

Every integration test also ends with the global invariant check
(`tests/support/invariants.py`), so damage beyond the test's own assertions is caught.
In mutations M01 and M06 the invariants caught the damage independently of the test
body.

## Findings while verifying

- **Two protections had no test.** One was heartbeats keeping a task that runs longer
  than its lease; the other was dropping a stale report for a run that retention has
  deleted. Both now have tests that kill their mutations (M21, M17).
- **One test caught its bug only sometimes.** `test_queue_timeout_restarts_after_retry_wait`
  went through real workers. When a worker claimed the promoted retry before the
  queue-timeout sweep, the bug went unnoticed, and mutation M27 survived. It is now
  deterministic, calling the scheduler steps directly. The end-to-end version remains as
  `test_queue_timeout_with_retries_end_to_end`.
- **Equivalent mutant M15.** Retention's status filter is redundant, because a database
  CHECK constraint makes `completed_at` NULL for every active run. It is kept as defence
  in depth and for the partial index.
- **Scheduler restart has no mutation.** There is nothing in memory to remove. The
  protection is that retry timing lives in `tasks.next_attempt_at`. The test still
  checks the outcome in PostgreSQL.
- **Tenant isolation is checked through HTTP responses, not DB rows.** That is the right
  layer for an access-control claim.
- **Simulated versus real.** Several engine-level tests simulate expiry by setting
  `lease_expires_at` in the past. That makes them deterministic and fast. The same
  behaviours are covered with real time and real processes by the process tests
  (SIGKILL, SIGSTOP, no heartbeats, outages).

## Keeping it true

- `tests/unit/test_docs_consistency.py` fails if `failure-model.md`,
  `correctness-audit.md` or `state-machines.md` cites a test that doesn't exist. It also
  fails if a failure-model row names no evidence.
- `scripts/mutation_check.py` fails if any mutation survives unexpectedly. It also fails
  if a source edit no longer matches exactly once, so a refactor cannot silently turn a
  mutation into a no-op. CI runs it.
